# Hospital Indoor Navigation Project (Hospital Nav)
## Developer Onboarding & Repository Structure Guide

This repository contains the source code for the **Hospital Indoor Navigation System**, a cross-platform Flutter application engineered to provide seamless indoor routing, turn-by-turn multilingual directions, and offline tracking (PDR) inside large hospital environments.

---

## 1. Project Directory Structure

Below is an overview of the directories and files within the codebase:

```
hospital_nav/
├── .github/                   # CI/CD pipelines & pull request templates
├── android/                   # Native Android configuration (Manifests, Permissions)
├── ios/                       # Native iOS configuration (Info.plist, Sensor usage descriptions)
├── assets/                    # Bundled read-only resources
│   ├── data/                  # Floor-wise JSON graphs (defining nodes & edges)
│   ├── lang/                  # Localization JSON files containing instruction templates
│   └── maps/                  # High-fidelity SVG floor blueprints
├── docs/                      # Architectural specs, diagrams, and reports
├── lib/                       # Primary Dart application source code
│   ├── controllers/           # High-level routing orchestrators
│   ├── models/                # Static data models and schemas
│   ├── providers/             # Stateful reactive controller stores (using ChangeNotifier)
│   ├── screens/               # Core user-facing app layouts
│   ├── services/              # Pure algorithmic utilities and native API wrappers
│   ├── widgets/               # Reusable UI component blocks
│   └── main.dart              # Application bootstrap entrypoint
├── pubspec.yaml               # Package manifests and asset declarations
└── README.md                  # This file
```

## 2. Directory Breakdown & Developer Usage

### 2.1 `lib/models/`
Defines the core data models used to represent the navigation graph, routing structures, and positions.
*   `node.dart`: Represents a physical point in the hospital. Nodes can be of type `room` (destinations), `junction` (corridor intersections), or vertical transits (`lift`, `stairs`, `ramp`). Contains coordinates `(x, y)`, `floor`, and accessibility attributes.
*   `edge.dart`: Represents a walkable pathway between two nodes. Contains the metric `distance` weight (in meters) and whether the path is `bidirectional`.
*   `nav_graph.dart`: The memory container representing a floor's graph, holding the node lookup table and adjacency list representation of edges.
*   `floor_config.dart`: Holds scale details (`pixelsPerMeter`) and asset pathways for Ground Floor through 4th Floor.
*   `navigation_instruction.dart`: Defines the structured output generated by the NLG engine, mapping maneuvers to language-specific guidance strings.
*   `route_result.dart`: Contains path nodes, metric distances, visited floors, and turn events for a calculated route.
*   `user_position.dart`: Represents the current coordinates and heading of the user's avatar.

*   *Developer Action:* If you need to extend node attributes (e.g. adding department tags), modify `node.dart` and update the JSON serialization parser in `graph_loader_service.dart`.

### 2.2 `lib/services/`
Contains the business logic, mathematical algorithms, and hardware interfaces.
*   `pathfinding_service.dart`: Solves the shortest path problem using the **A* Search Algorithm**. It dynamically processes adjacency lists and incorporates a `floorPenalty` (500 meters) to keep routes on a single floor unless necessary.
*   `pdr_service.dart`: Interfaces with raw motion sensors (accelerometers, gyroscopes, magnetometers) via `sensors_plus` and step counters via `pedometer`. It triggers step callbacks and tracks device heading.
*   `sensor_fusion.dart`: Combines raw sensor signals using a complementary filter to obtain a stable, drift-free estimate of the device's orientation relative to magnetic North.
*   `path_tracker.dart`: Tracks user progression along computed paths. It projects step lengths onto active path vectors and tracks deviations to trigger re-routing if the user walks off-path.
*   `instruction_formatter.dart`: The Natural Language Generation (NLG) engine. It flattens nested localization JSON trees and cycles through template variations to prevent repetitive instructions.
*   `transliteration_service.dart`: Implements phonetic transliteration maps across five languages (English, Hindi, Kannada, Tamil, Telugu) to keep proper hospital nouns recognizable.
*   `audio_service.dart`: Manages native platform Text-to-Speech (TTS) bindings and maps country locales (e.g. `kn` -> `kn-IN`).

*   *Developer Action:* If you want to modify pathfinding weights or heuristics, edit `pathfinding_service.dart`.

### 2.3 `lib/providers/`
Provides state management and propagates model updates to the UI layer.
*   `navigation_provider.dart`: The central state controller. It orchestrates floor switching, start/destination selection, path calculations, step snapping updates, and re-routing.
*   `pdr_provider.dart`: Tracks sensor telemetry and controls PDR calibration settings.
*   `settings_provider.dart`: Stores user preferences (accessible routing settings, voice options, language).
*   `simulation_provider.dart`: Animates the navigation indicator along the route for testing.

### 2.4 `lib/screens/` & `lib/widgets/`
Contains the visual interfaces and layout controls.
*   `map_screen.dart`: The primary dashboard featuring the map viewer, floating panels, search sheets, and active trip metrics.
*   `map_view.dart`: Handles touch gestures (pinch-to-zoom, panning) and aligns visual SVG maps with routing coordinates.
*   `path_overlay.dart`: Renders the route polylines, start/destination markers, and turn indicators over the SVG.
*   `directions_panel.dart` & `navigation_panel.dart`: Display turn-by-turn lists and dashboard controls.

## 3. Important Configuration & Build Files

*   `pubspec.yaml`: Declares dependencies (e.g., `flutter_svg`, `sensors_plus`, `pedometer`, `permission_handler`) and registers assets under `assets/data/`, `assets/maps/`, and `assets/lang/`.
*   `android/app/src/main/AndroidManifest.xml`: Standard Android configuration. Requests permissions for:
    *   `android.permission.ACTIVITY_RECOGNITION` (required by Pedometer)
    *   `android.permission.HIGH_SAMPLING_RATE_SENSORS` (required for responsive gyroscope readings)
*   `ios/Runner/Info.plist`: Standard iOS configuration. Includes string descriptors explaining the use of motion sensors and pedometers to the user.

## 4. How to Set Up the Environment

1.  **Windows Developer Mode:** You **must** enable developer mode on Windows before running `flutter pub get`. This allows Flutter to create symlinks for native plugins (like `pedometer` and `permission_handler`).
    *   Go to **Settings** -> **System** -> **For Developers** -> Enable **Developer Mode**.
2.  **Install dependencies:**
    ```bash
    flutter pub get
    ```
3.  **Run compilation:**
    *   **Debug Mode:** `flutter run`
    *   **Release Mode (Native performance):** `flutter run --release`
